## 積み残し

優先度順。着手時はこのファイルを更新すること。

### 退会すると注文の記録も消える（要マイグレーション）

`deleteAccountAction` は user を物理削除し、`orders.user_id` が `ON DELETE cascade`
（`drizzle/0001_orders.sql`）なので、お届け済みの注文も一緒に消える。領収書は適格簡易請求書
なので写しの保存が要り、プライバシーポリシーの「ご注文の記録は、退会後も税法・商法上必要な
期間保存します」とも食い違う。`user_id` を nullable にして `ON DELETE SET NULL` にする
（SQLite は表の作り直しになる）か、user を論理削除にする。2026-10-29 のレビューで判明。

### 領収書の続き（適格請求書まわり）

- 一部返金した注文の領収書に、返金日・返金分の税率が無い。返金が 1 万円以上なら
  適格返還請求書の記載事項を満たさない（`refunded_at` は DB にある）
- 「発行日」に出しているのは支払い確定日（`paidAt`）。取引年月日として出すなら見出しを合わせる

### BtoB の発注機能

承認フローと卸価格の表示は実装済み。残るのは**発注そのもの**で、`/shop/business` は
いまも卸価格表の閲覧までしかできない。

**決まったこと（2026-09-24）**

- 注文の受け方は **発注依頼 → 請求書**。取扱店がケース単位で発注依頼を送り、こちらが在庫と
  送料を確かめて確定し、請求書（銀行振込の案内）をメールで送る。入金の確認は管理画面で付ける。
  オンライン決済（Stripe）は使わない
- 支払い条件は取扱店ごと。初回は前払い、2 回目以降は月末締め・翌月末払いにできる
  （いまの `/shop/business` の説明どおり）
- 送料は**注文ごとに確定**する（クール便の料金は箱数と地域で変わるため、発注依頼の時点では未定）
- 1 ケースは **300ml・180ml とも 15 本**

**着手できない理由: 国内の卸価格が決まっていない**

卸価格表の注記は「税抜の参考価格（アジア向け CIF 概算）・最小ロット 1 出荷 3,000 本」で、
国内の取扱店に 1 ケースから売る価格とは読めない。国内の卸価格が決まるまで発注機能は作らない。
決まったら、国内と輸出で価格を分けて持つか（`product_price` に列を足すか）を先に決める。

### 商品カタログ

価格と在庫は D1 へ移したが、**銘柄そのものの追加・文言・画像の変更は引き続きデプロイが必要**
（`src/data/fujisan-products.ts`）。ストーリーや写真は運用で日々変わる値ではないため、
いまのところこれで困っていない。

- 入荷予定・ロット・賞味期限の管理は無い
- 在庫切れ間近のメール通知は無い（`/admin` のアラートを見に行く必要がある）
- 商品ページは静的書き出しなので、残数そのものは出していない。価格と完売は
  `/api/catalog` からハイドレーション後に反映する

### 管理画面の続き

ダッシュボード（売上・要対応・在庫・直近の注文）、注文一覧の期間絞り込みと CSV、
納品書、個人顧客の一覧、招待中の一覧、領収書の宛名は実装済み。まだ無いもの：

- 売上の推移のグラフ（期間を選んで見る）
- 注文・商品・顧客・お問い合わせ・メンバーの**一覧の本文**は、ヘッダーと数字だけ
  新しい組みにしてあり、行の中身は以前のカード状のまま。ダッシュボードと同じ
  「表」の組みに揃えると読みやすくなる

## 技術的負債

### ~~`drizzle/` の journal がずれている~~（解消済み）

`0006` 以降が手書き追加で `meta/_journal.json` に載っておらず、`drizzle-kit generate`
を実行すると適用済みの列を二重に出力する状態だった。journal を SQL 15 本と
1 対 1 に揃え、現在のスキーマを `0014_snapshot.json` として置き直した。
`drizzle-kit generate` は「No schema changes」を返す。

`0006`〜`0013` の**中間スナップショットは無い**（当時の状態を復元できないため）。
`generate` は最後のスナップショットしか読まないので支障はないが、
`drizzle-kit up` / `drop` は使わないこと。

同じズレが再発しないよう `src/db/__tests__/migrations.test.ts` が見張っている
（SQL を頭から流して DB を作れること・journal が実ファイルと対応すること）。

### マイグレーション番号が一度衝突した

`0007` が 2 系統に存在した（`0007_product_sku.sql` と `0007_contact_message.sql`）。
ブランチを分けたまま両方でマイグレーションを足したため。ファイル名が違うので
`d1 migrations apply` は両方とも適用してしまい、**使われない表が本番に残る**。
`0012` で片付けたが、長生きするブランチでスキーマを触るときは番号を先に予約すること。

### 日付フォーマット

Workers は UTC で動く。日付を出すときは必ず `src/lib/format-date.ts` のヘルパーを使うこと
（`timeZone: "Asia/Tokyo"` を省くと JST 00:00〜09:00 の出来事が前日の日付になる）。
期間で集計するときは `jstDayStart` / `jstMonthStart` を使う。
ローカルの OS が JST だと気づけない種類のバグ。
